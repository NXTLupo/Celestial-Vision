Celestial Vision

Celestial Vision tells astrophotographers what is in their night-sky photos: it asks public astronomy databases which stars, galaxies, comets, asteroids and satellites were in that patch of sky at that moment, then has Gemini write the report from their answers.

Requests · vite.config.ts

Most database calls leave the browser through forwarders on the Vite dev server

Most astronomy services send no CORS headers, so vite.config.ts registers a forwarder for each one under /proxy/ on 127.0.0.1:4200. The browser calls Gemini, NASA NeoWs and Nominatim directly. When a forwarder request fails, satellites.ts and pluto.ts retry through the public corsproxy.io relay.

Astrometry.net publishes your photo

astrometry.ts uploads the image with publicly_visible set to y, so every solved image appears on nova.astrometry.net. It downscales the file to 1,800 px on the long side first.

Three keys travel in the bundle

The define block in vite.config.ts writes the Gemini, Astrometry.net and NASA keys into the browser code. The README asks you to keep any build on your own machine for that reason.

CelesTrak is asked every two hours at most

satellites.ts keeps the combined TLE text in localStorage for two hours. A comment in the code notes that CelesTrak answers 403 to repeat requests inside that window.

Pipeline · processImage() in App.tsx

The plate solution decides which checks can run

processImage() runs the same order for every upload. Astrometry.net's plate solution feeds three later steps: the comet survey, the satellite check and the asteroid positions all test objects against the field center and radius it returns, and each step skips that test when the solve fails.

Each magnitude names its source

App.tsx prefers a COBS observation, then a JPL prediction. When the COBS Planner and JPL values disagree by more than three magnitudes, it computes an estimate from the absolute magnitude and the Horizons distance and tags it as computed.

Stacked images change the satellite math

For a file such as Stacked_52_..._20.0s, the satellite check uses the sub-exposure length for crossing tests, because a trail can appear in one sub-frame only.

Old photos widen the satellite search

When the downloaded CelesTrak elements are more than seven days from the photo date, satellites.ts marks SGP4 unreliable and widens its scan, and the app falls back to SatChecker and Project Pluto.

Checks · services/gemini.ts and App.tsx

What Gemini receives and what the code changes in its reply

The summary call has the most room to invent things, so the code limits what goes in and rewrites what comes back. Its system prompt tells the model to summarize the identifications it is given, never to identify objects from the image, and to quote FactSheet numbers exactly or write "unknown".

Streaks and comets are written by code

App.tsx adds one entry per detected streak and pairs it with the best-ranked satellite: a Project Pluto match first, then a SatChecker match, then an SGP4 estimate. Comets that Horizons places inside the solved field are added the same way unless Gemini already listed them.

Weak entries get a second pass

resolver.ts tries a streak against its meteor shower table and the ISS before re-matching satellites at a wider tolerance. It then compares any entry that has coordinates with the planets, five bright asteroids and the three brightest comets of the date, and an entry that stays unmatched lists every database it tried.

The caption gets its own pass

generateInstagramCaption() finds AU distances and magnitudes in the caption and rewrites any that disagree with the FactSheet: a distance off by more than half and by more than 0.5 AU, or a magnitude off by more than two. It then trims the text to Instagram's 2,200-character limit.

Run it

Run it on your own machine with your own keys

You need Node.js 20 and npm. The dev server binds to 127.0.0.1 on port 4200 with strictPort, so it exits when another process holds that port. Without keys, the upload screen and the review step work and the comet survey runs; the run then stops at the Gemini summary step with "Analysis engine failed."

git clone https://github.com/NXTLupo/Celestial-Vision.git
cd Celestial-Vision
npm install
cp .env.example .env.local   # add the keys you have
npm run dev                  # http://127.0.0.1:4200
VariableWhat it unlocks
GEMINI_API_KEYEvery Gemini call. A finished report needs it.
ASTROMETRY_API_KEYPlate solving. Without it the app skips the satellite check, the in-field comet and asteroid tests, and the APPLAUSE plates.
APPLAUSE_TOKENOptional. The dev-server middleware sends it with plate searches.
NASA_API_KEYOptional. NeoWs falls back to NASA's DEMO_KEY, which has lower rate limits.
